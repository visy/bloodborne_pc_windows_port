## B6: boss music for guests

### How a boss's music starts (every map)

Each boss has a music-on event (EMELD name `ボスBGM ON_<boss>`, e.g. Laurence 13404853, Ebrietas 12424803, Lady Maria
13504803, the Chalice Dungeons' parameterised 12906792 / 12906810 / 12906978) of this shape:

```
[0]  2000[2]   network sync
[1]  1003[2]   end if the boss is dead
[5]  3[0]      group 1: boss not dead
[6]  3[0]      group 1: the fight's start flag 1AAB48x2 on
[7]  1003[5]   skip 1 if MultiplayerState == 0 (Host)          <- args (u8 1, s8 0)
[8]  3[0]      group 1: the GUEST-ENTERED flag on               <- only for a non-host
[9]  3[2]      group 1: the player (10000) inside the fight area
[10] 0[0]      wait group 1
[11] 2010[4]   boss map sound <id> on                           (the music)
     ... the same block again for each phase change ([16]/[17] and Lady Maria's third, [33]/[34])
```

MultiplayerState (`0x17B21A0`, docs/party/cutscenes_endings.md): 0 Host, 1 Client, 2 Multiplayer, 3 Connecting,
4 Singleplayer. So alone or as the host the wait on the guest-entered flag is jumped over; a client waits for it.

The guest-entered flag (1AAB48x1 / x9) is set by ONE event only, the boss's guest-entry event (`ゲストがボス部屋入場_*`,
e.g. 13404851): own chr type 1 (a client) AND the fog's action button pressed, then the step into the arena region
(or a 2 s time-out that does NOT set it). Rom's is set by her landing event 13204821 (`ゲストが着地`: 13204800 on and
the player in the landing region at the same moment). Reader scan over all EMEVD: these flags are read by the music
events (and two boss-camera events, 12204804 / 12304804) only.

The shape `1003[5](1, 0)` followed by `3[0]` occurs in the game's scripts ONLY in the boss music-on events (scan of
every EMEVD: 55 hits, all `ボスBGM`; the other `1003[5]` + `3[0]` pairs are `1003[5](1, 1)` "skip if Client", in the
wandering-madness / treasure events).

### Root cause

In a party a guest gets the music only if it pressed that boss's fog itself. Fights the guest enters without a fog
press never played it on the guest:
* first fights that start by the host's action in an open room (bossfog FirstFights `action`: Ebrietas, Rom,
  Laurence, Lady Maria): the guests are in the room before the start, the fog is not up for them yet;
* the Hunter's Dream fights (Gehrman 12104803, the Moon Presence 12104853): no fog at all (0.7.7 fixed these two with
  fixed-id skip rules, BossRoomRules);
* Rom when the guest lands before the host (13204800 not yet on during the landing).

### The event's instruction cursor (static, 0x12ECDC0 event step -> 0x12EF2E0 advance)

The event object holds a cursor at +0x80: +0x98 the instance's parameter block (set for every instance), +0xA0 the
instruction index, +0xA8 the runtime (-> +8 the EMEVD file base), +0xB0 the current instruction record
(`index * 0x20 + event's instruction offset + header +0x28 + base`: the file's records, contiguous), +0xB8 a heap copy
of the CURRENT instruction's argument bytes with the event's parameters substituted (made by 0x12EF2E0 when +0x98 is
set, freed at the next advance). So the previous record is `+0xB0 - 0x20`, but its arguments must be read from the
file (base + `[base +0x78]` + record +0x10), never through +0xB8 (the first try did: it read the 3[0]'s own `01 01`
and never matched).

### Fix (party_phantom.h BossMusicEntryWaitSkip, seamless_rules.cpp BossMusicSkip)

In the EMEVD dispatch filter (0x17B93A0 hook, `EmevdDispatch`): a `3[0]` whose previous instruction record
(`instr - 0x20`: the event's records are the EMEVD file's 0x20-byte records, bank +0, id +4, arg size +8,
arg offset +0x10) is `1003[5]` with args `01 00` is skipped, on every role (on the host the skip-if-Host already
jumps over it). The guest then waits as the host does: fight started + standing in the fight area. Matched by shape,
no ids, so it also covers the Chalice Dungeons' bosses and mods. Log once per event:
`boss music: event N [i] does not wait for the guest-entered flag F (as the host's; BB_PARTY_BOSS_MUSIC=0 off)`.
Default ON (a plain fix of the party's boss fights), `BB_PARTY_BOSS_MUSIC=0` restores the old behaviour (the 0.7.7
Gehrman / Moon Presence rules stay either way).

Proof: smoke `lm` (group `boss_music_action`), see the end of this file.

## C2: boss AI with the host dead

### What was already found and fixed (0.7.7 / 0.7.8, docs/party/enemy_ai.md)

1. Dead players stay in the enemies' target bank (SprjTargetBankManager `*0x553B098`, vector begin +8 / end +0x10,
   scanned by `0x12ADC50`, no HP check); spectate carried the dead host's chr onto the followed guest (0.2 m), the boss
   idled over the corpse. Fix DeadPlayerUntargetTick (`BB_PARTY_DEAD_UNTARGET=0` off).
2. The boss's goals follow the AI's per-chr hate record (AI = boss vfunc+0x160 -> +0xB0 -> +0x560, kind-1 entries from
   +0x18: flags +2 (0x81 / 0x82), +0x20 type, +0x38 seconds, +0x40 active, +0x50 handle), set by the "attacker of a
   hit" path `0x12A9230` (type 3, 10.0 s). ChangeTarget (`0x1299CD0` -> `0x12AD1B0`) moves only the active entry
   (flags 0x87). Fix BossLockEntry writes the record for the chr BossAttentionTick hands the boss to.
3. Perception (`0x12AB4C0` -> holder vtable `0x531B9F0` +0x18 -> `0x12A85C0`, bank search `0x12ADC50` mode 0) only
   sees bank entries whose `[entry +0x18] +0x30 -> +0x18` bit 0 (the dead mark) is clear; a member's copy re-created
   by a wipe's re-join kept the mark, so no enemy perceived it once the host was down (Amelia's second try).
   Fix LivingTargetMarkTick (`BB_PARTY_LIVING_TARGET=0` off).
4. The limbo's once-a-second ChangeTarget to the nearest living member (LimboBossTargetTick,
   `BB_PARTY_LIMBO_RETARGET=0` off) only marks for one tick; perception is what keeps a record alive.
